# 深度多跳网络调研（Antigravity 原生版）

依托 Antigravity 内置 `search_web`（必要时结合 `curl` / 网页正文抓取或 `agent-browser` 读取官方 `.md` / 文档页原文），按严谨的多跳交叉验证流程产出可核查的研究结论，不依赖任何第三方私有 API Key。

## 调研步骤

1. **先拆维度，一轮并行发出**：
   - 把问题拆成 3–5 个互不重叠的检索角度（例如：官方文档/规范、发布日志与版本时间线、竞品或替代方案对比、真实工程踩坑/Issue、性能与成本数据）。
   - 在同一轮并行发起全部 `search_web` 调用（需要限定来源时传 `domain` 参数，如 `github.com`、官方文档域名），不要一条条串行试探。
2. **看摘要筛源，抓原文再下结论**：
   - 检索摘要只用来筛选最权威的 3–5 个一手来源（官方文档、GitHub Release/源码、RFC、论文或一手评测）。
   - 关键事实（版本号、价格、配额规则、API 签名、默认行为）**必须读原文确认**，不靠搜索摘要直接拍板；摘要与原文冲突时以原文为准。
3. **交叉验证与时效标注**：
   - 重要结论至少有两个独立来源印证，或直接出自唯一权威一手源（官方文档/源码）；仅单一二手来源的必须显式标为「单来源，未交叉验证」。
   - 时效性强的内容（模型列表、定价、版本特性、政策）一律注明来源发布或查阅日期。
4. **第二跳补盲**：
   - 读完第一轮原文后，针对新浮出的关键词、版本差异或来源分歧发起第二轮并行检索；通常 2 轮即可收敛，不无限发散。

## 输出结构

- **结论与建议在前，论据在后**：先给明确判断和选型建议，再展开对比维度与依据。
- **严格区分三类信息**：
  1. **已核实事实**（每条带原文 URL 与日期）
  2. **来源分歧 / 未确认项**（写清查过哪些来源、分歧点在哪）
  3. **基于事实的推断与建议**
- 查不到就直说查不到，列出已排除的检索方向，绝不用似是而非的内容补位。
- 调研篇幅较长（如多方案技术选型、完整竞品对比）时，输出为结构化 Antigravity Artifact 文档（配 Mermaid 架构图或对比表），终端只发核心结论与决策要点。

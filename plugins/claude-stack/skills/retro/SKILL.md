# 复盘

用户点名要**复盘**。你要改进的是 AI 干活的**环境**，不是评价这次活干得好不好：让下一次会话更少犯同样的错、更少花冤枉钱、更少让用户追问。

改写自 mattpocock/skills 的 `retro`（MIT），按本机这套规则和工具调整。

## 步骤

1. **定范围**。用户点了会话就看那几个；没点就看当前会话。Antigravity 当前/历史会话转录在 `~/.gemini/antigravity-cli/brain/<conversation-id>/.system_generated/logs/transcript.jsonl`（若复盘 Claude Code 会话则在 `~/.claude/projects/<cwd 转义路径>/*.jsonl`；在装有 `sessmem` 的机器可用 `sessmem search '<主题>' -n 5`）。转录很大，用脚本统计和抽段落，不整段读进上下文；多个会话或大转录派 `researcher` 去读，只要结论和证据。
   完成标准：说得出看了哪几个会话、各多大、从哪找到的。

2. **找候选**。按下面「七类」逐类过一遍，每类都要有结论（找到几条，或「这类没有」）。每条候选必须带证据：转录里的位置（会话 id、第几轮或时间）、原话或命令、出现次数、花了多少钱或多少次调用。没证据的不列。
   完成标准：七类都过了，每条候选都有证据。

3. **定去处**。每条候选按「放哪儿」那一节选一个最窄的落点，写清要改哪个文件、改成什么样（一两句草稿），估算改完能省什么。
   完成标准：每条都有落点和草稿。

4. **交给用户**。按严重程度排（花钱最多、用户追问最多、会出事故的在前）。每条写成一个拍板项：建议、理由（证据数字）、不回时怎么做。条目少就在终端讲完；多于 5 条或要配图表的，写提纲派 `reporter` 出 HTML 页，终端发结论加链接，拍板仍在终端问。
   复盘本身不改文件。用户点头后再改；动全局规则和 `~/.claude/agents/*.md` 前照全局规则先给原文。

## 七类

- **绕路**：找一个文件、一个事实花了很多轮。看有没有该加一句指路的地方（仓库 `CLAUDE.md` 的一行指针、续做文件、记忆），或者是不是信息本来就该放在更好找的位置。
- **能交给检查的错**：AI 犯了一个本可以被自动检查拦住的错（格式、类型、测试、禁用写法、改生产没授权）。先看仓库已有的检查命令和 CI 里有没有、是不是没接上或静默坏了；仓库完全没有门禁本身就是一条。
- **规范该谁管**：审查的时候漏了一个问题。机械能判的（固定写法、禁用接口、文件放错地方）做成钩子或 lint，判断题才交给 `reviewer` 的风险清单。规范放在审查那一侧：审查的人只看 diff、上下文压力小；写代码的人要探索、要调试，规则越少越好。
- **规则文件太长**：全局或仓库的 `CLAUDE.md` 里有只在少数情况才用到的内容，挪进子代理定义、skill 或文档，原处留一句指针。
- **工具太贵**：某类调用反复出现又很贵（整文件读大文件、一次次轮询、重复派子代理、临场换高档模型、截图读进主会话）。统计次数和花费，给出更便宜的做法；需要的话写个小工具或钩子。
- **空话规则**：规则里有模型本来就会照做的话、两处重复的话、用「不要 X」写的却能正面说的话。逐句看，删整句，别只删几个字。
- **缺信息**：关键信息 AI 拿不到，只能猜或者问用户（服务日志、第三方后台的只读权限、测试账号、某个决定的来由）。看能不能接上只读访问，或者把来由写进记忆。

另外两类是本机常见的，也要过：

- **用户追问**：用户说「没看懂」「为什么」「不是这个意思」「你又……」的地方。每处找原因：汇报写法、没带默认值的拍板项、没写去向的问题、误解了语音转写。
- **拍板与授权**：拍板项漏答、默认值没执行、等授权等了很久、AskUserQuestion 被当成授权。

## 放哪儿

由窄到宽，选第一个够用的：

1. **钩子或检查**（`~/.claude/hooks/`、仓库 lint / CI）：机械能判的一律放这里，比写成规则可靠。改了钩子要补正常、失败各一条测试并验红。
2. **仓库 `CLAUDE.md` / `AGENTS.md`**：只跟一个仓有关的。
3. **子代理定义** `~/.claude/agents/*.md`：只跟某个子代理的做法有关的。
4. **skill**：一套只在特定任务才用的做法。
5. **全局 `~/.claude/CLAUDE.md`**：所有会话都要守的；最贵，每一轮都在上下文里，能放别处就别放这。
6. **记忆或续做文件**：用户拍过板的决定和来由、没做完的事。

同一条只放一处。和已有规则冲突的，写明改哪条、怎么改，不另起一条。

## 产出格式（每条候选）

- 现象：一句话，带证据（会话、位置、次数、花费）。
- 根因：为什么会发生。
- 建议：落点 + 改动草稿。
- 预期：能省多少（钱、调用次数、追问次数），怎么验证改完真的变好了。
- 不回时：默认怎么做（通常是「不改，记进续做文件」）。

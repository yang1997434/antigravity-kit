# 复盘

用户点名要**复盘**。你要改进的是 AI 干活的**环境**，不是评价这次活干得好不好：让下一次会话更少犯同样的错、更少浪费额度、更少让用户追问。

## 步骤

1. **定范围**。用户点了会话就看那几个；没点就看当前会话。Antigravity 会话转录在 `~/.gemini/antigravity-cli/brain/<conversation-id>/.system_generated/logs/transcript.jsonl`（若复盘多会话或大转录，用一次性 Python 脚本统计和抽段落，或派 `researcher` 只读分析，绝不把大转录整段塞进主会话上下文）。
   完成标准：说得出看了哪几个会话、各多大、从哪找到的。

2. **找候选**。按下面「七类 + 两类常见项」逐类过一遍，每类都要有结论（找到几条，或「这类没有」）。每条候选必须带证据：转录位置（会话 id、步骤或时间）、原话或命令、出现次数、消耗了多少调用或额度。没证据的不列。

3. **定去处**。每条候选按「放哪儿」选最窄落点，写清要改哪个文件、改成什么样（一两句草稿），估算改完能省什么。

4. **交给用户**。按严重程度排序（浪费最多、用户追问最多、可能出事故的在前）。每条写成拍板项：建议、理由（证据数字）、不回时怎么做。条目少就在对话里讲完；超过 5 条或要配图表时输出结构化 Antigravity Artifact（或在有 `report-publish` 的环境派 `reporter` 发页），终端发结论与拍板项。
   复盘本身不改文件。用户点头后再改；动全局规则和 `~/.gemini/config/plugins/claude-stack/agents/*.md` 前照全局规则先给原文。

## 七类排查维度

- **绕路**：找文件或事实花了很多轮。看是否该在仓库 `AGENTS.md` / 续做文件 / 记忆加一句指路。
- **能交给检查的错**：AI 犯了本可被自动检查拦住的错（格式、类型、测试、禁用写法、未授权改生产）。查仓库门禁和 CI 是否缺失或静默失效。
- **规范该谁管**：审查漏了问题。机械能判的做成 `hooks.json` 钩子或 lint，判断题才进 `reviewer` 清单；写码侧规则越精简越好。
- **规则文件太长**：全局 `AGENTS.md` 里只在特定场景用到的内容，抽进子代理定义或按需 Skill，原处留指针。
- **工具太贵**：反复出现的高成本调用（整文件盲读大文件、零碎轮询、高价模型看大量截图、反复返工）。统计次数并给出降本方案或钩子。
- **空话规则**：模型本来就会照做的话、两处重复的话、能正面说却绕弯写的话。直接删整句。
- **缺信息**：关键信息 AI 拿不到只能猜或问用户。看能否接入只读查询或沉淀到文档/记忆。

另查两类高频问题：
- **用户追问**：用户说「没看懂」「不是这个意思」「你又……」的地方，回溯汇报写法、默认动作、语音转写歧义。
- **拍板与授权**：拍板项漏答、默认值没执行、授权边界拿捏失误。

## 放哪儿（由窄到宽，选第一个够用的）

1. **钩子或检查**（`~/.gemini/config/plugins/claude-stack/hooks/` + `hooks.json`，或仓库 lint / CI）：机械能判的一律放这里，改完必补正常/失败单测并验红。
2. **仓库 `AGENTS.md` / `GEMINI.md`**：只跟单个仓库有关的约定。
3. **子代理定义**（`~/.gemini/config/plugins/claude-stack/agents/*.md`）：只跟某个专职角色有关的做法。
4. **Skill**（`~/.gemini/config/plugins/claude-stack/skills/<名>/SKILL.md`）：只在特定任务按需加载的做法。
5. **全局 `AGENTS.md`**（`~/.gemini/config/plugins/claude-stack/rules/AGENTS.md`）：所有会话都必须遵守的铁律；最贵，能放别处绝不放这。
6. **续做文件或知识库**：用户拍过板的决定、来由与待跟进事项。

## 产出格式（每条候选）

- 现象：一句话，带证据（会话、位置、次数、消耗）。
- 根因：为什么会发生。
- 建议：落点 + 改动草稿。
- 预期：能省什么、怎么验证改完真的变好了。
- 不回时：默认怎么做（通常是「不改，记进续做文件」）。
